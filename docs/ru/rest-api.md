# REST API для интеграций

Внешняя система работает с XAgent через REST API `/api/v1` от имени **служебной учётной записи**: управляет проектами, базами, вебхуками и расписаниями, читает чаты, алерты и расследования.

## Где описание

Описание API открыто без входа в XAgent:

- `https://<адрес XAgent>/api/docs` — страница Swagger UI со всеми операциями;
- `https://<адрес XAgent>/api/docs/openapi.json` — тот же документ в формате OpenAPI 3.1, для генератора клиента или Postman.

В боковом меню XAgent на эту страницу ведёт пункт **OpenAPI**.

## Ключ

Каждый запрос несёт ключ служебной учётной записи в заголовке `Authorization: Bearer xagent_sa_…`. Вход в интерфейс XAgent API не открывает, а служебная учётная запись не может войти в интерфейс.

Ключ выдаёт администратор установки в разделе **Admin › Service accounts**:

1. **Create service account** — новая учётная запись.
2. Права: системные роли учётной записи или участие в проектах с ролью, как у человека (см. [`rbac.md`](rbac.md)).
3. **Issue key** — выбрать срок жизни: 30 дней, 90 дней, 1 год (по умолчанию) или без срока. Ключ показывается один раз: скопируйте его сразу.

Ключ, срок которого истекает в ближайшие 30 дней, отмечен в списке. Ненужный ключ отзывается кнопкой **Revoke key**: следующий запрос с ним получит `401`.

## Первый запрос

Из Swagger UI: нажмите **Authorize**, вставьте ключ, раскройте операцию и нажмите **Try it out**. Запрос уйдёт в эту установку.

Из командной строки (`-k` — для самоподписанного сертификата установки):

```bash
curl -k -H "Authorization: Bearer <ключ>" "https://<адрес XAgent>/api/v1/me"
```

Ответ называет учётную запись, которой принадлежит ключ.

## Ответы

- Ошибки приходят в формате problem details (`application/problem+json`, RFC 9457).
- Время — ISO 8601 в UTC с `Z`.
- Списки принимают `limit` (1-200, по умолчанию 50) и `cursor` и отвечают `{ data, nextCursor }`.
- `401` — ключа нет, он отозван или истёк.

## События писаря заметок

Лента записи о проблеме может содержать `kind: "note_writer"`: фоновый писарь закончил разбор закрытой записи. Поле `message` сообщает исход: записи сохранены, нового нет, работа пропущена или произошла ошибка; без причин, написанных моделью. Подробная причина доступна только в представлении писаря с проверкой доступа к основному и всем сохранённым прочитанным источникам. Это служебное событие, поле `user` равно null. Клиент должен принимать новый вид события, а незнакомый вид показывать как обычную строку ленты. Событие остаётся после удаления источника и траектории писаря через 90 дней.

## Как выключить

Настройка `PUBLIC_API_ENABLED=false` в `.env.production` (см. [`install-guide.md`](install-guide.md)) выключает API: запросы к `/api/v1` получают `503`, страница описания и документ — `404`, пункт **OpenAPI** пропадает из меню. Приём алертов по адресам `/api/projects/...` работает и с выключенным API. Применяется после перезапуска `xagent-core`.
